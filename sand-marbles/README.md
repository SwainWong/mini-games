# 沙里有珠 · 宝藏争夺战

纯 HTML / CSS / JavaScript Canvas 游戏。十五张独立设计的地图，划开沙土，让珠子直接落进正在移动的同色罐口。

## 星级与状态

- 只有全部珠子实际装罐才通关；失败、进行中没有星。
- 根据各关显示的挖沙额度评 1～3 星。只计算玩家新挖掉的沙；重复经过空洞、石块、蚯蚓挖掘不计费；用时不计分。
- 沙量为固定 560 × 760 逻辑画布中挖掘面积 / 100，向上取整。地形区域高度 564，底部是罐子和搬运区。
- 关卡随时可选，本次页面内保留最高星级、最少通关沙量及总完成数。更少挖沙会显示改善量，较差重玩和失败不覆盖最佳记录。刷新回到第一关并清空进度、关闭音效。没有后端、存储、账户或分析请求。
- 三档铲子：精细半径 14、常规 24、宽铲 34。没有提示按钮、默认解法线或运行时解法接口。

## 地下冒险队

- **盗宝人**从第二关出现。首次挖沙后准备 0.8 秒，以 22/25/28 逻辑像素每秒的基础速度沿真实路线挖向未入罐珠子，A* 绕开石头，已有通道内速度再乘 1.85，每 0.35 秒重新追踪目标。铲子实际够到任意珠子即失败，不按时间自动判负，不显示数字倒计时；接近时有距离警示、扬沙和可关闭的紧张音效。未动手、说明/选关弹窗、后台和结算时不推进。不会抢罐内珠子，其挖沙不计玩家沙量。
- **蚯蚓**从第五关起每关 2—4 条，以 41—57 逻辑像素/秒穿行，挖出半径 17 的真实岔道。每条有独立活动区域，碰到岩石转向，不会挖掉石块或永久卡在斜角。蚯蚓的真实位置与画面一致。
- **搬罐队友**从第三关出现。每趟随机选罐、方向、步长、停歇时长和折返距离。碎步行走、负重停顿、擦汗、摸下巴思考、抬罐共六个生成动作；走一段歇一段，回原位稍长休息。所有罐口留在完整人物可见的安全范围内，相邻罐口不会重叠。
- **罐子就是唯一接珠目标**：罐身、罐口、颜色标签和已收集珠子一起移动。每个物理步按珠子与移动罐口的相对轨迹判定入罐，包含抱起时的高度变化。旧位置没有接珠盘、隐形判定或暂存队列。落入错色罐子或错过罐口失败；可以保留沙层，等罐子停下再放珠。失败后可查看冻结地图和实际失误位置，查看时不会推进物理或显示解法。
- 已移除地震、风口、黏土、闸门和磁石，包括物理、绘制、声音和说明。

桌面采用插画工具侧栏，手机采用紧凑工具区、触控按钮和三列选关。连续六秒基本静止的珠子会显示停留数量，状态反馈不包含解法。

四种珠子继续保留：玻璃珠、带十字纹且更重更大的重力珠、回弹较强的环纹弹力珠、缓慢下落的菱形纹轻盈珠。

## 图像和声音

先用内置 Image 生成统一的 2.5D 黏土卡通素材，再接入 Canvas。搬运工与所抱陶罐属于同一张动作素材，手掌直接握住外侧把手，消除独立手臂/罐体叠加穿模。六帧分别标定罐口位置，移动、抬起和换帧时仍与物理罐口一致。静止陶罐、盗宝人和岩石、蚯蚓同样使用生成贴图；颜色罐口、铭牌与收集数量由代码叠加。盗宝人身边没有文字标签，威胁由移动、挥铲、扬沙、近距离光晕和可关闭音效表达。素材与提示词见 `assets/README.md`。运行时不调用图片生成服务，全部素材加载完成前不会开始游戏，加载失败可重试。

音效默认关闭，由用户按钮开启 Web Audio；挖沙、碰撞、装罐、胜负、蚯蚓、脚步和喘气均本地合成。关闭立即停止当前发声，不在后台继续播放。

## 验证

```sh
node --test sand-marbles/tests/*.test.cjs
python3 -m http.server 4192 --bind 127.0.0.1
```

`core.test.cjs` 检查评分和挖沙计量；`mechanics.test.cjs` 检查实时罐口接珠、旧位置漏接、移动高度、错色及搬运行为；`levels.test.cjs` 用实际物理执行十五关解法和四组随机搬罐种子，测试专用 timing.cjs 记录放珠前等待时间，运行时不加载。浏览器脚本通过真实鼠标/触屏输入检查通关，不调用自动获胜接口。

运行浏览器关卡回归前，将 `browser-check.js` 的 `/* SOLUTIONS */ null` 替换为 `JSON.stringify(require('./tests/solutions.cjs'))`，写到忽略的 `output/` 中，同时将 `/* TIMING */ null` 替换为 `JSON.stringify(require('./tests/timing.cjs'))`，再交给 Playwright CLI 的 `run-code`。`rival.test.cjs` 检查真实挖掘、抢夺、岩石、边缘目标、暂停和回合重置；`browser-rival.js` 通过真实鼠标等待抢夺并以 CDP 触屏完成第二关，检查音效、暂停、失败和刷新。

`browser-moving.js` 专门以真实触屏验证搬走目标、成功、漏接、重来、音效与刷新。脚本支持 URL 参数 `verifyFrom` / `verifyTo` 选择验证范围。

`pressure.test.cjs` 检查首个竞争关的实际威胁时间、蚯蚓挖穿真实路径及岩石转向、随机搬运状态和完整人物安全范围。
