# v18 可用性改进：独立设计审核

审核人：本轮独立专业玩家2。日期：2026-09-19。依据：实际7局报告 `final-player-gameplay.md`、委托的六项改进及当前源码只读核对。**不修改代码，不预给实现后的评分。**

结论：六项方向可实施，与已知原用户要求基本一致。必须保留“开局自动运动、回填后自动恢复”，不得把我的旧建议“准备状态/恢复缓冲”转成新的强制停顿。以下补足应作为本轮设计约束一起实现；不需要再向用户重复确认。

## 1. 自愿“看图暂停”：通过，补足状态边界

- 正常进入已可玩的关卡后，计时、盗宝人、矿车继续自动运行。不得等待首次挖沙/点击开始；不新增强制准备页。现有首次机制介绍可按第2项精简，但不扩张成每次开局门槛。
- 暂停时完整地图清晰可见，不加模糊或遮挡路线的中央大卡片。按钮切为“继续游戏”，旁边小状态明确“已暂停，不能挖沙”；不能只是时间停而盗宝人/引线/小炸弹继续跑。
- 冻结所有游戏推进，包括回填/小炸弹的独立表现队列；无静默倒计时。恢复时不补跑暂停期间的delta。
- 进入与退出暂停都清理当前按压和pointer capture，恢复后新手势才能挖沙；**新手势要求只限制挖沙输入，不能限制世界自动运行**。暂停中拖动、触摸抬起或切后台，恢复时不可连出横跨地图的旧线。
- 暂停、图鉴、选关、后台状态必须组合正确：关掉其中一个界面不应提前解除另一种暂停；重来/切关/刷新清除旧的自愿暂停，避免重来后无声停住。

## 2. 首遇图鉴两句主信息：通过

- 每项保留一句“会发生什么”+一句“我能怎样应对”，概率和完整细节用可点击展开内容。展开/收起不改变游戏规则或计时状态。
- 折叠不能藏掉会直接改变玩家决定的核心风险。例如问号袋主文仍写“可能得分，也可能爆炸或回填；想稳妥可以绕开”；落石主文保留“占车位”，引线炸药保留“可能伤车”。具体概率、范围、恢复细则放展开层。
- 首遇多个机制时一屏尽量看到所有短卡；展开操作和开始按钮在390宽度可触达，已有未读状态不能因折叠被误标记已了解。
- 图鉴主句与完整规则使用同一语义来源，避免短句还写“全部珠子+10”，而废珠实际仅+3。

## 3. 每色结果与最高可得构成：有条件通过，计数口径必须先固定

这是最容易产生新误导的一项。不能直接把历史loss事件次数按颜色累加作为“被盗颗数”。现有破袋/弃袋会追回原珠，再被偷也可能重复发生。

必要口径：

- 结果表按**原始珠子身份的当前/终局去向**计数，列“已接 / 尚未追回的被盗 / 错接 / 漏接”；可注明“被盗按未追回计，曾被偷后收回不重复统计”。同一颗不能同时落在已接和被盗列。满载弹开但仍在场内的珠子不算漏接。
- 若时间到仍有场内珠、手中珠或地上弃袋珠，增加“剩余未结算”列或明确脚注；不强行归成被盗/漏接。各色总数应能与原始该色珠数核对。
- 每色“已接”是颗数；得分另显示实际10分/废珠3分。宝袋20/40、宝箱30另列“宝物加分”，不能根据开袋触发珠子的颜色归给该色接珠分。总分必须与HUD一致。
- “最高可得”建议明确命名“剩余得分上限”，点击说明这不是保底、不是期望分，也不承诺在剩余时间里一定能拿到。
- 构成至少分：①场内自由珠；②盗宝人手中、尚未装袋的珠；③地上可拾回弃袋；④盗宝人袋内**可能追回**的珠；⑤未开宝袋/宝箱的奖励上限。①必须排除②；地上袋与盗宝人袋互斥；逃出矿场的袋不算可追回。
- “可追回”应写“可能追回/需触发条件”，不能给正常小袋、将逃出的袋承诺必回。不要读取预定随机结果提前告诉玩家某袋必爆炸/必回填。
- 当前珠子上限受到对应颜色车斗是否完好、容量、落石占位与能否清除影响。不能直接把各类珠子数量×10相加作为HUD数；废珠按3。优先用统一计算结果生成构成说明，与提前失败判断共用一份依据。若类别之间争同一车位导致各自理论值不可相加，展示“珠子原值合计 / 车位约束后可得上限”，并注明约束，避免各行加总与标题不一致。
- 未知问号袋上限是每袋40分（不是平均收益18分），只有仍有可能触发时才计入；宝箱固定30分另列。点击说明弹层也应明确是否暂停，推荐按图鉴相同规则暂停，关闭后自动继续，不把打开后的陈旧数字当实时状态。

## 4. 问号袋高风险标记与概率：通过，已核对分布

`magic.js`当前分布为：**50%得20分、20%得40分、15%小炸弹、15%回填**。因此“70%金币、15%小炸弹、15%回填”准确；展开层同时列50/20的金币子概率，防止误会70%都得40分。明确每袋开一次，同次重来结果不变；不许因增加说明而重抽随机数或更改seed流程。

地图风险标记应在玩家碰袋前就可见，使用形状/文字（例如“! 随机风险”），不能只靠颜色；保持真实碰撞范围不变，不盖住附近珠子和可挖路径。它是“这类物件有风险”，不是泄露该袋已经选定的结果。小炸弹与引线炸药的说明、标记保持区分。

## 5. 回填结束提示与自动恢复：通过，须防覆盖与吞输入

- 最终回填完成时明确显示“沙流停止 · 游戏继续 / 重新按住划线”，自动恢复计时和世界推进，玩家可自行点暂停。不得新增点击确认、首次落笔才计时或隐含恢复保护期。
- 提示应至少能读完一次，不能同帧立即被普通+0/收集气泡覆盖；不遮挡珠子、车斗口或风险区域，非模态且不接管画布点击。
- 仍按着旧指针时不能自动续画；应提示松开后重新按住，释放pointer capture，移动事件不能接回旧起点。这与自动恢复世界并不冲突。
- 连续多个回填/魔法效果排队时，不能第一个结束就误报“可以划线”。以实际 `inputLocked` / 世界暂停队列是否解除为准；手动暂停尚未解除时改为“回填完成 · 已暂停”，不自动取消玩家暂停。

## 6. 手机操作灯/气泡、受控车呼应：通过

- 390视口下优先保证文字大小、对比度与核心画布，不能只把整个右下操作员放大挤进车斗。气泡可以移至车轨下方或紧凑HUD区，必须避免遮住接珠口、满载珠和落石。
- 同色车的呼应同时加文字/轮廓或标识，不能仅靠颜色；只标出**当前主动受控车**，被推着走的邻车不应也标成被接管。
- 操作员惊吓刹车、逃岗、回岗、切换车时，灯/指向/车上标识同步更新。无人控制时不要仍亮出“正在控制”的旧色。不会改变车速、轮控顺序、指向方向或四车上限。
- 放大后的展示层使用非交互覆盖或明确不拦截画布手势。必须检查390宽度下底部重来/暂停按钮、横屏以及长文换行无溢出；鼠标窄视口不替代实体触控验证。

## 本轮实现后的必要验收

1. 同seed正常自动开局与重来，不依赖第一次输入；主动暂停可完整读图，时间/角色/炸弹/回填不推进，关闭后自动继续且不补时。
2. 一颗珠先被偷、掉袋、回收、再被偷/接到的流程：按色去向不重复；废珠+3和宝物加分汇总正确；超时未结算珠不丢项。
3. 满车、落石占位、破车、多颜色、手中珠、弃袋、逃出矿场、未知袋场景下，明细与HUD上限/提前失败同源一致，不泄露随机结果。
4. 真正的回填后立即普通指针补路，确认结束提示可见、自动恢复、旧手势不续画；叠加手动暂停和连续回填也成立。
5. 桌面与390真实浏览器完整局、失败复盘、暂停恢复、重来刷新；至少一场多车和一次回填，不用单测截图替代。

设计审核结论为“按以上补足可进入实现”，不代表实现通过或新评分达标。旧报告90/86/85仍只是旧版本体验记录，改进后的分数必须在新一轮独立真实试玩后产生。
