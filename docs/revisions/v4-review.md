# 国王消消乐 v4 — 制作人方案与验收评审

日期：2026-09-17。角色：本项目唯一小游戏制作人 / 高级游戏美术设计师 / 审批负责人。

## 本轮结论

**批准按照本评审细化后的 v4 方案进入实现和 image 资源制作。** 此处只批准方案，没有批准成品、评分或发布。v3 的评分及发布审批不适用于 v4；旧记录保留。

用户最新要求优先：黄石不能和宝石、厚挡板发生可见重叠；胜利改为消除全部砖；image 生成完整国王多帧姿态；低 HP 受刺存在概率性高能推盾。当前提案方向合理，下面列出的规则是本次批准的组成部分，不能省略后仍宣称通过。

本轮重新检查了 `king-match/engine.js`、`king-match/renderer.js`、`king-match/levels.js` 及 v3 设计。旧版斜坡是线段碰撞，而画面有厚度；贴图外缘与碰撞圆也需要一起核对。v3 评审主要覆盖下落旧槽、明显穿砖和因果行为，没有以密集接触的逐帧几何误差作为硬门槛；这解释了漏检，不能把旧“未见持续穿石”当作不重叠证据。v4 要补对应测试与放大画面。

## 必须纳入的细化

### 1. 可见轮廓和实体统一

- 斜坡、底板、边缘、第二关石台统一采用有厚度的实体轮廓。绘制和碰撞读取同一个几何定义，边框厚度也计入外形，不保留画厚板、撞中心线的路径。
- 黄石位图不透明主体必须位于碰撞半径内；不能发生数学圆已分离、金色贴图仍盖到砖上的情况。可保守扩大碰撞圆或缩整颗贴图，不得靠画砖覆盖、裁掉金子来遮掩交叠。
- 下落宝石使用从上一物理位置到新位置的扫掠检测；粒子、砖组和固定实体联合求解。最后投影必须再满足所有邻近约束，不能刚推出砖，又推进厚板或相邻砖。
- 纠正只发生在接触附近；不允许删粒子、把金子送到出口、跨墙搬运、暂停金子等待动画结束，或制造旧位置的隐形支撑。满仓容量仍来自真实可用空间。
- 运行时绘制 y 与碰撞 y 同源。采用保守包围形状是可以接受的卡通近似，但必须明确而稳定。

验收不能只看正常一次通关：覆盖静置满仓、斜坡两端、料口、落砖夹金、砖列相接、石台边角、爆发推挤；每类保存放大帧及最大穿透量。稳定接触的实心轮廓不应有肉眼可见交叠；目标几何残差不超过 0.5 画布 px，瞬态若出现持续超过一帧的约 1px 以上穿透，列为阻塞。粒子守恒和正常出料同时成立，不能用增加遮挡层“通过”截图。

### 2. 全清胜利与有限棋盘

- `remainingColored` 只统计彩色可消宝石，固定石台必须视觉上属于地形，不计“全部砖”。HUD 主进度改为剩余宝石；排出颗数可以作为统计，但不是隐含胜利条件。
- 最后一组宝石实际爆裂移除后，只要同一物理步 HP>0，即满足胜利并关闭供料。可以播放完成演出，但不得再要求旧配额、低压两秒、必须离刺或额外点击。若同一步 HP 归零，失败优先；在胜利成立后不再偷偷结算伤害。
- 两关新图必须使用包含真实重力、分段石台、全部连锁的全清求解，保存完整解法见证；“出口可连通”不能代替全清证明。初始没有自动三连、有多个合法选择，正常全清不依赖爆发随机。
- 初盘存在全清解，并不等于每条合法路线都能全清。允许玩家走错，但必须处理剩一两颗、没有合法交换或仅剩不可消孤岛，不能把它们伪称“再等等会消”。出现无步应清楚提示重排/重来。
- 重排只改当前占用格颜色，不补砖、不挪石台。候选必须找到全清见证才提交并扣次数；搜索没有找到时，保留原盘和次数，提示“当前结构暂未找到全清方案，可重来”。搜索预算耗尽不等于已证明无解。
- 确定性无解（例如只剩 1–2 颗）要提供明确重来出口，不能悄悄清尾砖。若选择立即给出“无法全清”败局，需与 HP 归零原因区分；也可以保留游戏并显示持续可见的重来说明。不得用隐藏自动消除兜底。

关卡难度以实际试玩定标，不固定旧版 3/5 步。重点是开始阶段能够在压力下做有效决策，疏通后仍有全清目标；第一关不应在正常思考速度下只靠概率爆发才能完成。提示同样优先全清路线，预算外只承诺合法交换。

### 3. image 完整人物帧

批准生成同一国王的完整身体帧：建议 8 帧，4 帧受压退步循环、1 帧受伤、2 帧高能动作、1 帧稳定姿态。资源均为 image 生成的位图；不是把旧人物裁成躯干和两条腿重新摆动。

所有帧使用同尺寸画布、透明背景、相同人物尺度、共同脚底基线及持盾手锚点。逐帧检查王冠、脸、服装、手指与双脚完整一致，没有白底、额外肢体或明显跳变。运行时只能按完整帧裁取/播放及整体位移；不能把一个帧再次切成手脚局部补动作。

盾可继续作为单独的物理物件，但人物帧的手必须对齐同一盾锚点，资源中不能再多生成一面重复盾。也可整帧包含盾，但此时禁止另画一面，且每帧盾面都必须与相同实体位置吻合。尖刺接触依据身体实体，换帧不能让人物看似提前穿刺或凭换姿态脱离危险。

退步播放由实际位移/速度驱动，静止不得原地疯狂踩步；爆发只在物理事件发生后播放。降低动态效果设置可减少闪光，但不能隐藏 HP 伤害或爆发状态。

### 4. 低血概率爆发

批准初始调参：实际尖刺伤害结算后，`0 < HP <= 40` 且不在爆发/冷却中时，独立 35% 概率触发；持续 2.2 模拟秒、从激活时刻开始冷却 8 秒、每局最多成功触发 2 次。

每个合资格伤害事件只抽样一次，未触发不消耗成功次数；持续接触下一次真实伤害可再次抽样。冷却或爆发中不叠加、不刷新时长。HP=0 必须先判败，不抽到爆发复活。多个伤害事件各有机会，因此整段危险期至少一次爆发概率会高于35%，不能将35%宣传成整局概率。

随机源与矿石随机严格分开，可注入独立测试种子以覆盖触发与不触发。不能每帧抽样，不能让额外点击、暂停、读取 snapshot 改变结果。

爆发增加实际抵抗/前向驱动力，产生连续的盾位移，接触面传递冲量将黄石推出。不要直接跳盾位置、清除盾前金子或暂时关闭碰撞。必须检查旧的前推速度上限是否使“高能”肉眼不明显；可单独校准爆发速度上限，但仍须扫掠及连续碰撞。爆发不回血、不免伤、不自动消砖；尚接触尖刺时伤害照常，实际离刺才停伤。

## 实施批准与新的验收顺序

1. 先修共享几何、贴图边界及密集动态碰撞，保留残差/守恒数据。
2. 同步生成完整国王帧并由本负责人看图审批；允许修正帧一致性，不付费、不删原资产。
3. 用全清求解重做两关、重排及胜负边界，再校准压力与正常操作时间。
4. 接入独立随机爆发，覆盖不触发、触发、冷却、上限、HP0和接触中仍扣血。
5. 本负责人再次独立真实浏览器试玩：先不读解法的有限盲玩，再针对全清、卡尾、重排、碰撞高压、概率爆发和移动触控专项复验。需要观察自然未触发局也能正常全清；专项随机测试可使用已声明种子，不能伪称随机抽到。
6. 最后重新评分游戏设计、可玩性、物理可信度、美术动作、交互稳定性。硬性新要求任一失败就不批准，不以旧评分或均分抵消。

**当前批准实现，尚未批准 v4 成品和上线。** 不需要向用户再次请求这些免费、无删除操作的审批；仍由本负责人承担审批。评审证据引用仓库相对路径，后续在本文件追加，历史结论保留。

## 正式设计与计划复审

已读取 `docs/revisions/v4-design.md` 和 `docs/revisions/v4-plan.md`，**批准这两份文件进入实现及免费 image 图集制作**，同时执行上面的细化条款。第二关石台改为 4 格宽可以批准，以分段全清和物理排流实测为准，不必保留旧的 3 格宽布局。

互锁三连/四连可作为离线构造方法，但成品棋盘不能只重复同一种小模板，让玩家每次都照同一格交换；仍要有多个真实选择，且第一关教学易读、第二关有新的分段/连锁决策。

求解剪枝特别提醒：存在四连、五连和交叉消除时，“某颜色数量不能被 3 整除”不是无解条件，不得这样剪掉可解盘。某颜色只余 1–2 颗、且本次搜索不允许重排，才可据此排除该三消分支。重排候选既要有全清见证，也要维持无初始自动匹配，避免按重排立即白送全清。

### 当前阻塞与改进

**物理运动连续性仍阻塞最终批准。** 主 Agent 的额外密集错误路线发现联合投影曾把夹住的金子单步横移约53–62px。最终穿透接近0并不足以通过；这种横穿整列的纠正依然不可信，不能用截图终态掩盖。认可改为金子实际接触时暂缓落砖、转成横向滚出、空出后再落，同时维持列顺序。

若夹腔真实封闭，横向根本没有出口，就不能等待后又执行大幅投影。正常全清见证必须在满仓也能完成结算。错误路线若构成物理无进展，应明确显示堵塞及重来入口，不可无限锁输入，不可删除或暗传金子。最终复验增加这条密集夹挤路线的连续位移记录。

两项小改进已发出：无步说明应围绕“宝石尚未全清”而不是旧“通道未接通”；爆发口号和普通受伤文字避免同时覆盖王冠上方。主 Agent 已反馈正在修正。

图集原图此前仅通过静态素材审批。最终新版仍须完成两关全清、剩砖不胜、末组全消立即胜、144px完整帧/盾锚点、密集夹金连续性、自然或声明种子的高能碰撞、移动布局和状态边界复验，然后给新的评分及发布结论。**此轮不评分，不批准发布。**

### 原阻塞的解除证据

厚斜坡、端盖和砖实体读取共享几何；金子不透明主体收进真实碰撞圆。夹挤改为实际接触限制下落，允许金子从邻近开放方向移出；平台/砖角的联合投影补入近处斜向候选与前一合法位置；最后改为每块砖独立支撑，只有真实接触的砖/金子会阻挡它。封闭卡腔持续3.5秒无显著进展明确结束为jam，保留物理状态并允许重来。

我在冻结版独立运行 `v4-continuity.test.cjs` 和 `v4-geometry.test.cjs`，5/5通过；又独立运行“a supported brick cannot suspend unrelated falling bricks”，1/1通过。覆盖密集错误路线不跨整列跳位、两关30秒满仓仍可全清、厚板端盖、相邻砖联合约束、平台/落砖角邻近解及无关砖独立下落。
