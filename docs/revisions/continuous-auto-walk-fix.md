# 修复开门后停在原地

## 根因与复现

旧版 `Adventure` 只有通过手动 `advance()` 才会离开消除阶段，页面将它绑定在画布下方的按钮。普通消除没有任何自动推进路径。

线上1280×720实际鼠标操作中，门高156、配重209/43后继续等待6秒仍为playing；按钮y757至801位于视口外。独立审核员另以两次普通交换清空16颗宝石，等待约17.6秒后仍停在A，HP100、配重239/43、门已锁定。此前验收主动点击了前进按钮，遗漏了自然流程问题。

## 修复

- 引擎在消除阶段每一步先判HP0失败；存活、门已升顶锁定、宝石操作已结算时自动开始穿门行走。
- 移除手动前进按钮及绑定，更新玩法提示；无需清空所有宝石，也无需额外操作。
- 到达P1/P2才完成，不以门开代替到达。B入场仍是独立ready状态，未点击开始前不启动危险。
- 暂停冻结引擎与人物；当前段重试、刷新规则保持。
- 合入最新主干e95dd1d；其余游戏代码未修改。脚本加版本查询参数刷新客户端资源。

## 回归

12项连续关引擎测试通过。新增自动推进和全清两项测试先在旧引擎失败，修复后通过，另覆盖HP0优先。

`tests/browser-auto-walk.cjs` 为真实指针回归，断言页面不存在前进按钮，不提供注入或调用advance的路径。1280×720桌面先全清A、390×700触控保留宝石，两者均仅正常开始/消除完成A→B→P2，错误为空。行走暂停的状态与画布均冻结，刷新复位。

开发输出写在忽略的output目录，线上验收与独立审核结论另行补记。
