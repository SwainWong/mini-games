## 方案结论

**批准当前 v3 方案进入实现与免费资源准备。** 用户最新要求优先，本版使用 HP 取代碰刺即死、真实满仓取代稀疏供料、宝石重力与连锁取代永久悬空砖。方案已经同时处理三项变化的关联，未发现必须先改写方案才能实施的阻塞。

此处只批准设计。v2 的 8.32 分和发布审批不适用于 v3；v3 当前尚无成品分数、通关或发布结论。仍由同一负责人独立试玩、提出问题、复审后再决定是否上线。

## 已确认的核心选择

- **HP 100，接触 12 点、间隔 0.8 秒。** 第一次接触不能即死，持续接触到 HP 归零约有 6.4 秒窗口。实体尖刺止挡人物，伤害随实际接触，离开停止，没有自动回血。
- **真实满仓和可见顶部补入。** 初始黄石填满可达料仓与盾前空间，保留国王保护腔；画外库存不能施力或瞬移到刚清除的洞内。局部流动空隙合理，不能重新出现 v2 的大块空料仓＋零散落石。
- **仅现有宝石下落，不补新宝石。** 避免无限补砖持续封口；重力后顶部空位和累计消除共同创造排石空间，关图和目标重新求解，旧解法作废。
- **石台按格对齐、分段落位。** 石台上方砖落在真实支撑面，下方砖落到下段底部，石流从左绕行；不出现隔空支撑。
- **胜利继续看真实排流与安全。** 配额、HP>0、持续低压和离刺成立才获救；不以消除数量或演出直接置胜。

## 随实现执行的细化约束

这些属于当前批准方案的验收细化，可直接落实，无需再次找用户审批。

### HP 与接触节奏

伤害计时使用游戏模拟时间；暂停、玩法弹窗与后台暂停都不得继续扣血。首次进入接触时只触发一次伤害，持续接触每 0.8 秒一次，不按 120Hz 物理子步重复扣血。短暂碰撞抖动不得反复重置“首次接触”造成一秒多次额外伤害：全局受伤冷却或接触迟滞都可，必须保证新接触不绕过伤害间隔。

HP>0 时接触不结束游戏；国王被实体止挡，不能穿过尖刺或无限退到屏外。解压后角色真实离开尖刺，伤害停止，HP 保留已损数值。死亡只在 HP=0，接触演出与死亡演出要能区分。胜利与最后一次伤害同一物理步发生时，HP=0 优先判败，避免死人获救。

### 满仓与压力

开始前完成无明显重叠的密集初始化/安定，ready 阶段不能暗中扣血或推人。全体真实已生成颗粒满足 `spawned = active + drained`，待入料单列；重力处理不能以删除堵塞颗粒来制造孔洞。

用相同视角的时序画面确认：开始、运行 5 秒以上、疏通时主料仓持续呈高密度黄石；实体与人物保护腔之外不再长期露出大块空背景。无需把每个运动空隙涂满，但不能靠装饰石贴图冒充实际密集料层。容量上限、初始颗粒数和供料能力必须按完整仓体计算，不能沿用不足容量的旧上限。

满仓与减压必须同时成立：观察局部流动后盾面负载下降、退势停止或前推，同时上方主仓仍饱满。若必须把主仓排成空城堡才能救回，就没有满足新要求。若始终满仓导致任何通路都无法解压，也不能只降低伤害延长必败过程。

### 重力、连锁与物理同步

一次有效交换的结算顺序：交换 → 匹配高亮 → 爆裂移除 → 现有上方宝石加速下落 → 全部落稳 → 检测新横竖三连 → 必要时重复连锁。没有新的匹配就结束结算。重力本身不增加有效交换次数；连锁次数与消除量可单独显示。

下落中绘制与碰撞使用同一位置，不允许逻辑瞬移到底而画面慢慢落、或石头穿过尚在屏幕上的完整宝石。颗粒被移动砖挤开时保持守恒，不要默默删去夹住的石头；出现夹挤需在真实邻近空间解开，不可直接传到出口。

交换和重排只在落稳状态接受，快速输入不能插入半次结算。落稳后提示和无步判断针对新盘，而非旧坐标。重排仅改变当前占用格颜色，不重新摆满格子，不把石台或已腾空的顶部补回。

### 关图与可玩性

求解器必须包含重力和全连锁后状态，检测石台上下段，不能用 v2 永久孔洞的连通性代替新的物理可胜证明。起盘仍无自动三连，有多个合法选择；至少要真实体验多次选择造成不同的排流与压力后果，不能一按第一组就自动清到通关而全程无决策。

两关解法、步数和配额允许基于仿真重新定标；不继承 v2 四步/五步作为强制目标。制作人首次试玩不提前获得解法。正常路径可胜、错误路径可败、已经受伤但正确疏通仍能救回，三类都须通过。

密集颗粒和动态砖带来的性能成本须实测：操作响应和交换/下落应连贯，不能为了维持数量让输入明显卡顿或物理时间几乎不走。测试报告区分桌面 Chrome、模拟移动上下文与未覆盖的物理手机性能。

## 实施中几何修订审批：可见节流料口

批准延长上方斜坡并在右侧保留真实窄料口，代替旧的约 82px 宽口。目的为让主仓保持密集而下方井有足够排流能力释放盾前压力；这符合已批准的满仓/局部疏通边界，不改变用户要求。允许根据实际空腔容量等待新颗粒进入，画外排队仍不施力，严禁数值重叠压缩偷出无限空间。

28px 仅是初始校准值，接近两颗矿石直径，需检查自然桥拱堵口风险。若持续出料不稳定，可扩大至约 2.5–3 颗直径并重新校准，不需另向用户请示。必须验证可见料口与碰撞轮廓相同，无隐藏挡板或定时放石捷径；停料只由真实入口/仓体容量决定，不能由消除次数、配额进度直接控制。

成品需要录到至少 5 秒“上仓持续密集、料口自然输送、下方通路释放盾前负载”并存，并复核零输入仍会持续施压至 HP 失败、正常解法和受伤后离刺停伤。新几何及容量定义应回填设计文档。这个实施批准不代表成品验收或发布批准。

### 三项新要求及边界核验

1. **HP：通过。** 首碰 100→88 仍可操作；实体止挡保持 clearance=0；连续约 6.4 模拟秒耗尽 HP。独立触摸受伤后排流、离刺、两秒停伤及最终获救已完成。0.8 秒全局冷却、抖动不重复首伤、HP0 优先判败另经源码和测试交叉核验。
2. **密集供料：通过。** 开局、等待受伤和排流时都呈密集黄石主仓；保护腔留给人物，料口和通道允许真实运动空隙。自由错路持续压到死亡，正确路线实际反转退势，人物会前推。源码只有可见顶部有空槽时才生成，画外排队不施力；没有删石造假排流或画满装饰背景冒充粒子。
3. **宝石下落和连锁：通过。** 直接采得第 2 次交换的序列：1.058s swap → 1.550s fall → 2.017s cascade → 2.517s fall → 2.892s settled，actions 全程为 2。截屏核对下落位置、石台支撑和新直线三连。移动碰撞体与绘制同一 y；旧槽不保留幽灵支撑，见源码及动态碰撞测试。完整砖未见持续穿石或悬空。
4. **操作边界：通过。** 落砖中额外触摸没有插入新交换（actions=1）；暂停 1.1 秒墙钟前后模拟时间均 .592，HP均100，falling 完全相同。继续后可落稳。重排保持空格和石台位置，次数2→1；重来、刷新回 ready/100HP/0交换/初始石料。没有页面 JS 异常。
5. **移动可读性：通过。** 独立 390×844 无横向溢出，底栏 bottom=837.375，单格38.30 CSS px，真实触摸两关通过。HP 数字/血条、余地、宝石颜色和尖刺可区分。主 Agent 360×800 证据为底栏800、单格36px；尺寸属于较小但仍可用边界。

### 评审意见处理与可接受限制

唯一新增文字意见是：提示在搜索预算外会退回合法三消，原“试着接通落石通道”容易让人误认为提示保证通关。主 Agent 已改为“试试这组合法三消，再观察排石路线”，已查验源码。无须为此扩大算法范围。

第一关四种宝石加有限库存有策略深度，但自由路线需要多步看后果，提示也不总是最佳解；这使入门难度高于极休闲广告式消除，计入可玩性扣分。36px 窄屏格、五秒短教学遮挡下部一点区域也计入交互余量，均不阻塞这两关交付。

物理是卡通近似：圆形颗粒、有限退步速度、预定加速度的格子落位，宝石不会被少量矿石永久卡住。不能将其宣称为工程级刚体模拟，但本版的供料、接触施压、退步、止挡扣血、疏通离刺和颗粒守恒因果一致，满足小游戏的物理可信度。缓存优化后的性能证据是桌面 Chrome 模拟手机 6 秒区间约361帧、p95约16.8ms，游戏时间与墙钟接近；不是物理手机性能保证。
