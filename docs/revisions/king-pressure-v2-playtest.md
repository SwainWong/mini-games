## 评审方法与独立性

试玩者没有读取 `tests/solutions.cjs` 或开发者推荐解法，先由截图观察棋盘自行推导交换，使用局内暂停及静态截图进行规划；这不是人类反应速度测评。首次尝试没有使用局内提示或重排来获得解法。后续测试再检查提示和重排边界。

第一阶段 CLI 会话的截图/时间顺序出现不一致，为避免采集污染，正式时序证据改用全新 Chrome 进程和隔离 browser context，真实 `page.mouse.click` / `page.touchscreen.tap` 输入，并开启录屏。只读 `window.kingGame.snapshot()`，没有调用浏览器引擎交换方法、写状态或直接设置胜利。受控的无接触对照在独立 Node 实例进行，和真实通关证据分开。

## 三项问题与修复闭环

1. **触刺反馈被结果层遮掉。** 首版 lost 同帧出现模糊弹层，看不见真正触刺瞬间。修改为真实判输后约 0.65 秒接触圈/受惊后仰，再弹结果。独立手机复核：32.367s、clearance=-0.009、state=lost 时结果层仍 hidden；画面可见接触演出；0.9 秒后结果层出现。没有延迟真实判负或提前按计时判负。
2. **受压动作幅度不足。** 首版腿部最终变化在手机不足 1px，接近静态贴图平移。修改为手机约 2.4px 的交替蹬脚、压低与倾身，锚定实际盾位置；手机画面和触刺姿态复核可辨。仍是卡通分片角色动作，评分未把它当作完整骨骼动画。
3. **第二关三步捷径。** 首版第二关由试玩者独立发现 `[44,45] → [11,12] → [6,7]` 三步稳定解压，20.733s 就获胜，比第一关更短。开发只调整第二关颜色布局和接驳，未添加累计消除量门槛。新布局由试玩者重新观察推导，五步真实触屏通关；开发还加入 ≤4 步无贯通的穷举回归。

另采纳首关首次开始的局部交换箭头示范，不自动代操作。该提示已在独立 390×844 手机截图中验证。

供料并非有限初始库存：新黄石持续从顶部进入，生成计数随时间上升，直到救援或碰刺结束才关阀。画外队列不进入压力计算。

## 可接受限制

角色沿水平自由度运动，圆粒子近似矿石碰撞，速度有卡通上限；它们限制精密真实性，但实际接触变化已证明能减速、停住并反转。旧版固定盾耐久的缺陷已移除。两关仍为有限内容，布局固定便于学习和重试，重排只改余下颜色。没有将这些限制伪装成更多关卡或专业物理仿真。
