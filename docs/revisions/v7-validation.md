# v7：无有效交换的残局自动通关

用户要求覆盖了旧版“只有零宝石才获胜”的规则。截图中剩下的四颗宝石已不能通过相邻交换形成三消，不能再要求重排或重来。

## 行为

- 国王 HP 尚存，且交换、落砖、连锁、自动疏通均已结束时，宝石全部清空或已无合法三消交换都判通关。
- 已有自动三连会先消除。存在合法交换时继续游戏，即使全清求解器找不到一条全清路线，也不会把它误作无步可走。
- `no-moves` 通关保留真实剩余宝石及重排次数，关闭供料和危险计时；结果明确显示剩余数量、已无有效交换、关卡通过。`cleared` 仍显示全清结果，HP0仍按失败规则处理。
- 就绪说明、关卡提示、手册、人物和结果文案同步。补正手册及README遗留的旧“堵塞重来”描述，自动集金槽仍生效。
- 稳定棋盘按引用缓存终局检查，避免闲置时每物理子步重新扫描全部交换；正常交换、重排及落稳都会更新棋盘引用。

## 验证

- 修复前四颗残局测试得到 playing，修复后得到 won/no-moves，原四颗颜色和位置均保留。
- 新增六项终局测试；完整引擎套件53/53通过，包括有合法交换但无全清解不通关、现有三连优先、下落不提前结束、HP0优先。
- 旧物理回归仍保留：用真实七步后的可操作六颗尾盘替代单砖流量探针；给封闭夹缝构造加独立合法六颗区域，继续验证恢复后的有效输入，而非把所有旧 playing 断言机械改为 won。
- 可复用 `tests/browser-outcome-check.js` 使用真实输入到达与截图相同的四颗残局：46=蓝盾、48=绿宝石、52=王冠、54=红宝石。检查保留4颗的胜利文案、停止危险、进入第二关、全清结局、重开和刷新。

浏览器实测和发布状态由实际验证后追加。首次主Agent本地浏览器等待开始按钮稳定性超时，未算通过；宿主load高于350，已避免并发浏览器，并交给制作人单实例复验。
