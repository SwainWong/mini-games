# 国王消消乐 v5 — 斜坡末端排料专项评审

基线：线上 v4 / `0a7e4a6`。本次只针对用户圈出的斜坡右末端阻挡黄石下落，保留全清、HP、满仓、完整人物帧和概率推盾规则。唯一制作人继续审批；不新增 Agent、不付费、不删除旧资产。

## 当前审查结论

**批准先做最小出口几何候选的流量对比实验；尚未批准具体成品或发布。** 本轮未修改生产代码，也未新增素材。v4 评分不作为这次出口修正已通过的证据。

读取 `king-match/geometry.js` 可确认：斜坡为 `[[24,150],[366,232],[366,248],[24,166]]`，右墙 x408，实际净口42画布px。黄石半径6.8–7.5，直径13.6–15，因此口宽只有约2.8–3颗石头。末端还有16px厚的竖直边。尺寸支持“窄口形成短暂拱架或挂角”的可能解释，但必须用下游有空位时的实际通量与接触轨迹验证，不能只凭静态图片断言根因。

## 最小合理调整

建议第一候选：末端向左收18px至 **x348，净口60px**，约4颗最大直径黄石宽；保持上表面原来的斜率。对应上缘 y≈227.684、下缘 y≈243.684，厚度仍16px。移动量约一颗石头多一点，既让变化肉眼可读，又不需要改城堡、国王保护腔、右墙或宝石棋盘。

先比较原42px与60px。若流动仍被末端棱角干扰，再对下缘末角增加约6–8px小倒角，仍使用同一凸实体定义绘制和碰撞。也可在56–64px范围微调，以实际通量/连续性定尺寸；不要同时大改斜坡角度、供料、HP、人物阻力和颗粒半径，否则难以确认哪个变化解决了问题。

保持原斜率的好处是国王上方已验证的屋顶位置不变，只缩短右端。主仓依旧密集，从顶部真实补入；下方排料井宽度仍大于供料口，正确疏通应能卸压。不得以降低金子密度、减少石料总量、给金子凭空向下速度、关闭接触或删除挂住颗粒来得到“顺畅”结果。

## 必须同步的几何来源

`king-match/engine.js` 尚有与旧出口相关的硬编码：碰撞粗筛/最终纠正/overlap中的366和248、保护腔roof里的342/82、初始化roof的clamp366，以及右侧初始填充条件x>374。几何修改必须逐一检查，优先从 `G.RAMP` 派生边界与坡面；保持原坡率时也要明确哪些量不变，不能只改画面留下旧隐形末端。

顶部生成x范围的366是采样宽度，不应因为数字相同就机械替换；它与斜坡末端不是同一个意义。图形描边不能额外缩窄看起来可用的出口而碰撞仍按另一条轮廓。金子位图、碰撞圆、厚板外缘继续执行 v4 的一致性要求。

## 验收要点

1. **先区分堵塞位置。** 下方井/宝石把空间填死时，上游暂时不下料是正常后果；真正要修的是下游已有可容纳空间、主仓还有料，却长期挂在末端。用正常交换形成通路且保留少量宝石，避免全清立刻关闭供料导致误判。
2. **真实通量。** 在末端下方同一水平截面统计实际向下跨越的颗粒ID或净跨越数，至少连续10模拟秒；不将原地反弹反复计入吞吐。记录总量、逐秒流量、最长无跨越间隔、下游局部占有率。满仓且下游开放时，连续超过约1秒完全无下料需解释或继续修；细小脉冲与石头互相碰撞可以存在。
3. **真实满仓。** 同视角保留开始、5秒和10秒画面。上仓不能为解决流量变成稀疏背景；面积变化后的颗粒数应按实际空间解释，不能只通过改变stockFill分母获得好看的比率。未被疏通的棋盘仍应产生实际压力和HP危险。
4. **压力/保护不退化。** 两关静置仍受压，国王保护腔不进金；正确全清路线不需要爆发好运；受压撤退、高能前推和料口通畅共存。新增口宽不能让金子从屋顶与盾交界穿入人物腔。
5. **碰撞和连续性。** 末端上角、厚侧边、下缘倒角、右墙夹缝都要近景和几何残差检查；保持 v4 的穿透、逐子步连续位移、颗粒守恒门槛。不得用大幅投影跨过出口边缘，更不能靠画板盖住金子。
6. **端到端范围。** 两关真实鼠标/触控正常全清；固定石台、HP0、残局/堵塞重来不回退。保留最新其他游戏和主页修改。生成素材与人物帧不因这次微调重做。

最终报告要区分：几何尺寸选择、仿真通量对比、独立实际浏览器画面/玩法、发布及线上文件验证。完成候选对比后，由本负责人确认实际采用的尺寸与形状，再进行最终专项试玩和发布审批。
