# v6：内部落砖停滞恢复审查

## 当前结论

用户最新要求优先：**撤销 v4/v5 中将 `jam` / `PASSAGE BLOCKED` 判为失败的审批。** 旧报告保留为历史，不再作为该行为的依据。现阶段批准问题定位与恢复方案设计；具体恢复几何、状态转换及实测未提交，暂不批准成品或发布，也不沿用旧评分。

此前审核将“封闭夹腔不能穿透”与“必须让玩家失败”错误地绑定在一起。前者是物理约束，后者不是合理推论。内部实现选择了整盘必须落到预定目标才解锁，继而把这个实现的死锁当作玩家败局；这是验收漏项，应由系统恢复，而非要求玩家重来。

## 根因及不能接受的修补

当前 `engine.js` 的 `beginFall()` 先算整盘压缩目标，再以 `operation.kind === 'fall'` 保持所有砖的动态实体；只有每块砖到达目标才提交逻辑棋盘。`swap()`、`remix()` 以及页面输入均在 operation 存在时返回。任意一颗金子支撑住一块砖，就能锁住全盘。3.5 秒无进展判输只是结束这个锁定，并没有恢复可玩状态。

真正封闭的夹腔可以没有合法的二维逃逸方向。因此不批准以下替代：单纯删掉 jam 分支、无限延长超时、增大力直到穿出、回滚粒子位置、删除金子、直接计为排出、关闭碰撞、用遮挡掩盖穿砖、改为另一个失败文案。取消 jam 后继续锁住输入并让 HP 耗尽，也属于同一个问题。

## 建议实现方向与批准边界

优先保持正常棋盘、全清目标和现有顺畅落砖路径。无进展时进入独立的自动机械泄压状态；它属于系统恢复，不消耗重排次数、行动额度或生命奖励。触发与退出须有真实状态条件，不依赖无上限的重复随机抖动。

若采用“泄压/错层”，必须给出完整、可观察的排金路径。普通侧墙开口不能释放被砖围住的内部金子，不能把这种局部几何当作通用恢复证明。第二深度排金槽可作为设计候选，但必须让粒子连续进入可见入口、沿槽运动、越过真实出口后才计入排出，保留 ID 与守恒；不允许把“错层”实现为临时无碰撞或金子淡出。恢复关闭时不能重新生成金子、把金子塞回砖内或让扩大后的实体穿入粒子。具体路径和绘制方式还需提交审查。

若改为金子支撑的稳定局部棋盘，必须让真实稳定宝石可操作，且交换/三消由画面上真实位置与邻接关系决定。不能按未显示的压缩目标格匹配三连。还需说明所有可交换砖都不对齐时如何继续；只解锁按钮而没有任何可接受输入不算恢复。此方案会改变格点规则与求解器，不能作为只改一条输入判断的小补丁。

建议正常无进展约 1 秒内开始明确恢复，恢复约 3 秒内返回可交互状态，具体预算可依实际机制校准。若系统恢复期间必须独占输入，暂停国王伤害/后退的危险时钟，并明确显示短暂机械动作；正常可操作阶段仍保留压力、HP 与高能规则。恢复超时必须有已验证的无损继续路径，不能又以重来、HP0 或无限“恢复中”兜底。这个预算是待实现验证的要求，不是已经达到的事实。

## 必须验收的行为

1. 任何无进展检测均不直接产生 lost/jam；只有真实 HP 归零等既有玩家规则可失败，不能用输入冻结期间的强制耗血变相惩罚。
2. 复现原错误路线：第一关静置 30 模拟秒，再依次真实输入 `15↔23、34↔42、44↔52、40↔48`。保留每步开始/结束、恢复开始/结束、HP、粒子 ID、剩余宝石、可接受输入证据。修复后应可继续操作，不要求这条自由路线必然全清，但不能系统判负。
3. 保留第一关静置 10 秒的正常全清与每步额外思考 0.25 秒的路线，两关正常全清、第二关石台附近落砖、30 秒满仓后起手均不退化。
4. 封闭夹腔、开放挂角、独立列下落分别测试。其他没有支撑的砖继续落下；真实支撑不能用统一全列暂停掩盖。触发后再次发生停滞仍可恢复，不能只允许一次救济。
5. 全程逐子步验证固体穿透、位置连续性、生成/排出/在场数量守恒。上一版对自由空腔粒间短暂分离的窄例外不能扩展为跨实体、回滚或恢复传送许可。
6. 恢复不改变宝石颜色/数量，不替玩家自动消除，不消耗重排，不凭空改变 HP。若设计确实需要自动改变宝石位置，必须另行说明规则和全清求解一致性。
7. 恢复后在实际手机模拟上下文完成至少一次真实交换、提示、暂停继续和可选择的重来；重来必须是玩家自愿选择，不能是系统唯一出路。画面与碰撞采用同一可见恢复几何。
8. 所有测试中依赖 `sawJam`、reason=jam 或 jam 结果层的旧断言应改为验证恢复和重新接受输入；不能仅删除断言。新增无进展不败局单测只是第一层，不能替代端到端恢复证明。

## 具体方案复审：批准前置集金槽实现

主 Agent 提交了完整状态转换：正常 fall 连续约 0.6–0.8 秒无进展，选取与砖的当前位置至目标位置完整扫掠体相交的金子；保留 ID、x/y 与数量，约 0.2 秒连续抬升到 z=24 的前置槽。砖与墙的深度范围约 ±8，石头半径不超过 7.5，抬升完全离开主物理层后才让砖下降。砖按至多 336px、500px/s 的路径落到原格点；其间主场景/源流/国王危险时钟暂停。前槽金子沿可见输送路径移动至右侧 x416，再向下实际离场才计入排出。砖落稳即恢复操作，运输不必结束；后续可重复触发。

**批准该具体方案进入实现与免费现有素材复用，尚不批准成品或发布。** 这比局部非格点三消更能保留已有规则，也为封闭二维夹腔提供了明确的第三维出口。它属于显式的卡通机械辅助，不应宣称完全被动的二维刚体物理。设计中约 0.872 秒的抬升与最大落砖时长具有可验证的有限边界；需实测具体状态转换开销和后续连锁，不能只按公式宣布已经实现。

实现批准包含以下约束：

- 前槽必须通过完整边框、透明底面/阴影和连续抬升动作，清楚表现为架在棋盘前方的独立输送空间。前景石不得看起来嵌入砖面或从厚板内部穿出；普通石仍维持既有前后关系。功能槽可用描边与光效，金子继续使用现有生成位图。
- 扫掠选择计入完整砖宽高与石头半径。必须满足 `z - r > 实体最前深度` 后才允许跨主层砖的 XY 投影；抬升时砖不移动，未选普通石在恢复阶段冻结，避免新的石头进入扫掠体。
- 每颗前槽石继续计入 active；只在其完整半径越过真实出口后计入 collected。不得抬升即计排出，不能重选已在槽里的石头、复制 ID 或因运输动画结束而删除未到出口的石头。
- 系统恢复使用独立机械时钟，游戏危险时钟、伤害冷却、高能持续期一起冻结；仅暂停伤害函数但暗中消耗冷却/增益时间不合格。恢复不加动作、不扣重排、不改 HP/颜色/宝石数。
- 已有前槽运输与新一轮恢复能够共存。需要处理槽内排队和明显的石头互相重叠，不能让所有石头挤到同一个出口坐标；旧运输不能锁住新棋盘输入。
- 主仓数、前槽数、总 active 分别统计。前槽石不向主盾施力，也不能被误当成仓内占用导致源口永久停料。当前固定粒间索引容量 2000 与主仓上限 1600 需核查；连续恢复的总资源峰值必须有安全边界，超量不能通过丢石处理。

新增专项验收：记录 z 转换与主层/前槽数量守恒，验证至少两次重入恢复；检查老槽石尚未离场时新交换仍被接受、恢复后主仓继续密集补料。实际镜头须覆盖抬升、砖下降、透明槽跨越棋盘、侧槽排队及完整离场五个阶段。旧失败路径修复必须由真实输入重现，不能只构造单个无进展状态后检查 `state !== lost`。

## 运输轨迹细化批准与测试清单

**批准用覆盖棋盘的前置集金槽、独立重力与粒间碰撞、整个底部安全出口替代 x416 单粒宽输送口。** 右侧可有轻微导流，但不必让所有粒子先横移。此细化更新上一节的侧槽路径要求，其他无损、连续、有限恢复和分层约束不变。前槽应有明确两侧边界与底部接料口，金子完整越过底部后才排出。石台、盾及普通源流仍在主层，前槽不能贡献主盾负载。

可接受主仓最多 1600、总 active 最多 3200 时以源口背压保留 queued，并按需扩容粒间索引；不得通过删除运输中石头维持上限。需要报告 main/tray/total 三者峰值。恢复后前槽运输可继续，但独立实际试玩还须检查其是否遮住宝石或触控目标；尚不能因几何成立就判定画面通过。

已读当前 `v6-recovery.test.cjs`：只有“无进展不败局”的构造状态测试，正确但覆盖远远不足。建议实施后至少包含以下可观察断言：

1. **恢复可完成。** 同一封闭夹腔在有上限的模拟步数内回到可交互状态，并实际接受一次合法交换；不能只断言仍 playing。最大落距与零选中颗粒两种边界分别覆盖。
2. **分层先于落砖。** 从 z=0 开始记录抬升中间帧，未满足半径离开实体厚度时砖保持原 y；满足后连续下降。x/y 不能在抬升事件中跳到出口或目标。
3. **逐帧守恒。** 每步 `spawned = main + tray + collected`，ID 不重复、不丢失；supplied/queued 另按既有供料口径验证。前槽石完全越过出口前不得计 collected。
4. **计时无罚。** 设置低 HP、即将到期的伤害冷却和进行中的高能后触发恢复；验证独占期间危险时间、HP、冷却与高能剩余时间不暗中消耗。系统机械时钟继续，用户主动暂停则所有层都停。
5. **二次恢复。** 第一批前槽石尚未排完时再次触发，验证旧 ID 保留、只选主层颗粒、槽内碰撞正常、总上限/背压不破坏守恒，最终再次可操作。
6. **正常流程不退化。** 两关常规八交换全清、十秒延迟起手、三十秒满仓起手与旧错误路线均覆盖；常规可自行落稳的情形不应频繁进入辅助槽。恢复不直接消除或染色，不消耗重排/行动。
7. **图层碰撞口径。** 几何检查只比较同一深度相交的实体；这不是免除碰撞，而是需要新增 z 间隔断言。旧主层固体穿透、守恒与连续性测试继续保留。

最终实际浏览器需要保留恢复前、抬升中、砖下降、恢复输入但前槽仍有金子、完全排出的截图/日志，并在手机宽度验证可读性。当前仅批准实现细化，最终效果与发布仍待复验。
