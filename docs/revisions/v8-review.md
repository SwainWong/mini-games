## 国王行为状态与碰撞

建议主行为路径：`双手/单手撑盾 → 安全确认 → 放下盾 → 叉腰观察 → 预警举盾 → 撑盾`。单手、双手、背身顶盾是可见的撑盾姿态；受刺反应、高能爆发和死亡是更高优先级的动作分支，结束后返回与当前危险相符的姿态，而不是无条件回叉腰。

1. **安全确认不能只看本帧接触数。** 同时需要盾前无直接接触、平滑负载低于退出阈值、盾前及上方进料方向无将在举盾所需时长内到达的颗粒。低速正在靠近的石头、已堆在盾边但瞬时接触计数抖动，都不是安全。
2. **迟滞分开定义。** 无危险持续约0.6–1秒才进入放盾；预测危险一出现立即退出观察并举盾，不额外等同样长的确认时间。阈值/时间可仿真校准，但须用真实速度和距离解释，避免临界点反复闪切。
3. **实体随完整盾形变换。** 收盾时不能保留一面看不见的直立盾墙；举盾过程也不能瞬间把碰撞体插入金子。如果为举盾提前预留保护空间，应来自可见平台/墙的既有实体，不能追加隐形护罩。实际盾的平移/旋转应有连续碰撞或保守安全约束。
4. **预警必须覆盖举盾动画时长和最坏接近速度。** 不是只用固定小半径的“近了才举”；验收应从最高有效流速、垂直落石及侧向滚入分别验证不会来不及。若中途有石接触，动作与真实接触点同步，不能穿过去后再抬盾。
5. **姿态优先级。** HP0死亡最高；实际受刺事件触发短时肢体反应；高能与受伤可合理衔接，但不能让有效受刺只有红字没有动作。观察姿态不应被“残余接触力滤波”无限阻止，力实际衰减安全后须能进入。

建议状态机公开只读字段：行为state、当前完整帧、shieldPose、危险预测/接触标志与安全保持时间，便于验收，不提供浏览器写状态接口。

## 严格夹压碎金判据

建议每颗粒按稳定ID记录候选夹压时间，必须同时满足下列条件才累计，任一项失效即清零/退出候选：

1. 上方是**实际接触该颗粒的正在下降宝石砖**，且它的重力目标仍要求继续下降；仅位于远处未来扫掠区域不算接触。
2. 下方存在真实实体砖/明确作为砖材的固定石台支撑，形成上下对向夹持；单独压在金子堆、地板或贴墙的颗粒不能直接套用此授权。若需要通过接触链识别多颗夹层，应单独提交其判据，不能悄悄扩展为整腔删除。
3. 上下夹距在直径加微小接触容差以内，并且下落目标仍将关闭该间隙。不要要求已经出现实体穿透后才算夹压，也不能把尚宽于直径的可用缝隙算夹死。
4. 按**粒子半径膨胀后的实体几何**检查下方和两侧的连通逃逸路径。只探测左2px/右2px/下4px不足以证明封闭；有一条经过砖角的合法侧下通路就应保留粒子、继续滚动。其他移动金子造成的暂时拥挤不能作为永久实体墙来证明封闭。
5. 在约0.7秒持续满足夹持期间，没有有意义的净下落或沿可行侧路进展。速度低本身不是证据；需要同一ID的累计位移/夹持对象与拓扑证据。不同颗粒轮流接触不能共享一个超时计数。

受控范围内不能证明无逃逸，就保持金子，不可因搜索预算耗尽改判夹死。若该保守策略仍使输入停滞，必须修复局部解困/支撑逻辑，不能以重新加入jam败局或无上限等待兜底。实施阶段应优先用此前真实错误路线验证：只有严格授权颗粒碎裂也能恢复操作；若不能，需要再次提交更具体的恢复方案。

碎裂应有局部压缩/碎屑闪光，随后该ID转入crushed统计。碎屑仅是短暂视觉效果，不计为可施压金子，也不伪装成collected奖励。判定前不能先把粒子抬离接触再回头声称夹压。

守恒改为 `spawned = active + collected + crushed`；`supplied = spawned + queued` 保留。每个ID只能离场一次，crushed与collected互斥；clear/no-moves胜利、重来及换关均重置或继承各自正确局部状态。不得为方便测试修改生成计数掩盖缺失。

## 乐观网格封闭判定复核

主 Agent 提交 `h=4` 网格、膨胀半径 `r'=r−sqrt(2)h/2−epsilon`、8邻接且不排除角穿越的乐观搜索。**数学方向批准**：任一真实可行连续圆心路径映到最近网格点，偏移不超过 `sqrt(2)h/2`；距离实体的Lipschitz边界保证这些点在缩小半径图中仍自由，连续路径映射只需8邻接。因此只有连乐观图也无路，才可能作为确定封闭的证据；有乐观路不意味着真实粒子能走。

实现必须同时保持以下条件，否则上述说明不构成证明：

- 起点映射到最近网格点，epsilon覆盖现有同层数值容差；不能任意改选较远起点或把起点误判为不可达就直接宣布封闭。
- 目标也需乐观处理：例如网格点到未来扫掠体距离达到r'即可作为逃离候选。若障碍用r'而目标仍强制完整r，则可能漏掉真实连续逃离点量化后的位置，造成错误封闭。
- 搜索域须包含真实路径的所有可能网格投影；可达的有限搜索窗口边界应返回open/unknown，不能把窗口外当墙。顶部/底部边界按实际可离开范围和同样量化余量处理。
- 当前真实砖体构成障碍，未来扫掠体仅决定“是否摆脱待下落砖”的目标。其他金子仍不当永久障碍。
- 找到乐观路线但真实半径无法通行时保留为unknown。推动粒子只能沿真实半径微步检查可行的方向，不能沿乐观图强推穿角。

若大量unknown使恢复迟迟不结束，可以按h4→2→1→.5逐级细化，并保持每级相同乐观误差公式；细图也无路才确认封闭。搜索预算耗尽仍为unknown，不能触发crushed。由此保住慢流/窄缝反例，同时再以真实旧路线证明可恢复性，不能只验证删除正例。

## 局部连续疏通细化批准

已读当前 `clamp.js` 和真实卡点报告。当前对有几何出路的颗粒保持crushed=0是正确的保守行为；但只对上砖直接接触粒施力不足以移动其下方多层金堆，导致下游无法先让路。

**批准扩大连续疏通的候选到实际下降砖扫掠区内、具有真实半径逃逸路线的颗粒，逐颗施加受限滚动力。** 扫掠区只作选择范围，不作障碍、夹压证明或删除授权；颗粒始终留在原物理平面，不改位置到路径节点、不提走、不计crushed。下游先让路是允许的物理辅助。

实现约束：

- 正常顺畅下落或已沿可行路线取得进展的粒子不应额外引导。优先处理实际停滞且与下降砖压力/接触群有关的颗粒，避免整片自由落石表现为磁吸转向。
- 采用真实半径的路径与每步实体扫掠验证。乐观图只用于排除“确定封闭”，不能直接驱动粒子通过假开放窄角。速度/加速度使用有记录的有限上限，不能以一次大投影完成路径。
- 路径随砖和邻域变化重算；上砖已恢复自然下落或颗粒已脱离待疏通区域，立即停止对应引导，不在后台持续控制已排出的自由金子。
- 夹压碎金条件完全保留：上下真实承压、持续时间与乐观图封闭证明齐全才允许逐颗crushed。引导失败不能自动升级为碎金。

当前卡点报告出现候选持续18–22机械秒、stockFill=0，说明“未误删”本身还不够，不能以这种长时间输入冻结和主仓放空作为成品。新的疏通回归必须记录恢复耗时、最小上仓密度、位移/穿透上限及每次碎金证据，同时验证返回真实可操作状态。若源口冻结让仓内明显空掉，需要进一步合理的源控或更短恢复，不能修改密度分母或贴背景金子掩盖。此处批准实现改进方向，最终通过仍取决于实际旧路线与慢流反例。

性能需覆盖恢复区间：当前单次网格搜索可涉及约9千节点并逐砖检查，扩大颗粒范围后不能每个120Hz子步对所有颗粒重跑完整BFS。可按几何版本、粒径桶缓存导航，轮转重算失效路径；真实引导用桶内最大半径可保守，封闭证明用桶内最小半径可乐观，但目标与边界保持相应语义。计算预算耗尽仍判unknown，不可碎金。最终记录恢复期间帧耗时，不能只提交正常无恢复时的帧率。

## 逃逸语义纠正：自然疏通与有效接收空间

经真实tail路线复现，底部完整砖封底、上方下降砖持续压住多层金堆；任意方向几何搜索仍能找到必须向上回灌的路线，因此永不判夹阻，实际输入长期锁住。制作人承认此前“任何方向存在连续路径就一律不可碎”的要求过强：几何可达不等于重力与有限压力下可以自然脱困，不应把这种额外要求强加给用户。本节**覆盖此前所有要求任意方向完全几何封闭的审批表述**，保留历史用于解释修订原因。

**批准改为游戏中受重力约束的夹阻。** 允许下行、侧滚及最多约本颗直径 `2r` 的局部抬升来绕角；若唯一通路必须逆重力抬升超过该余量，不再以其否决夹压。不能改成完全禁止任何向上微动，否则会误删本可滚过低角的金子。上浮余量与位置量化误差需分开计算；乐观图可放宽该边界来保住真实允许路径的投影。

新的上浮预算边界是游戏定义的可自然脱困范围，不是一个可直接返回open的出口；人为裁小的搜索窗口边界仍需按unknown处理。该算法不再声称证明整个三维/二维空间数学封闭，而是受重力、有限局部翻滚与接收容量约束的游戏夹压判据。

同时批准目标从“中心移出下降砖未来扫掠框”修正为：

1. 到达真实出口；或
2. 完整圆脱离待下降砖扫掠区，且目的地此刻有容纳它的实际空位。

其他金子不当作整条路径的永久障碍，但可用于检查目的地是否有容纳空间。否则把一颗金子导向已完全填满的金堆仍称为“成功脱困”，并不符合实际压迫。乐观目标同样缩小当前颗粒半径以覆盖量化误差；容量检查仅忽略当前粒子自身，不能忽略整个候选群以虚构空位。

此修订仍须同时满足真实上下降砖/下支撑砖承压链、约0.7秒持续夹持和无真实净进展，逐颗碎裂后立刻重算。目的地容量不能只取一个拥挤瞬间：窗口内出现可接收落点、粒子已有慢速进展时退出候选；与候选可达区域相连的下游若持续外流，暂时满位属于排队，应保留并引导，而非直接认定夹死。地图另一侧无关流动不干扰本地判据。

审批目标是符合用户明确区分：上下砖持续夹住、无法自然疏通的颗粒可碎；正常下落、慢流或有可接收侧路的颗粒保留。批准按以上修订实现，不允许用固定超时无条件清除整个夹层来换取进度。

## 最终确认时长修订与物理交接

**本节覆盖本文件此前所有0.7秒或0.12秒夹压确认要求：当前标准为0.05机械秒。** 早期时长是制作人提出的实现参数，用户只要求真实上下砖夹压可碎、慢流/开放落石保留。真实复现证明0.1秒几何采样叠加长确认，会在每颗新补位后串行重等，使有效恢复变成20–30秒锁盘；这不应成为必须坚持的额外用户要求。现在直接承压候选约1/60秒复核，0.05秒相当于6个120Hz物理子步，普通疏通路径仍低频计算。

所有实质条件保持：同一颗真实直接顶砖颗粒、真实下方宝石承重链、受重力约束且没有可容纳落点的闭塞、没有颗粒自身新的净下落、逐颗碎后立即重算。上砖只在接触容差内贴近仍静止金子，不等于金子已脱困，不能统一重置同一持续承压事件；真实金子下移则重新计时。极慢连续0.024px/s下降12秒仍不碎的反例已通过。此前陈旧时长保留在历史评审段落用于追溯，不再是当前准入标准。
