# 国王消消乐

交换相邻宝石，横向或纵向连成至少 3 颗才能消除。消除会打开永久空洞，黄色落石在重力、斜坡和碰撞下穿过通道进入底部出口。上方持续供料；堆积接触盾牌会把国王向身后的尖刺推，身体后缘碰到尖刺即失败。

## 两关

| 关卡 | 排流结构 | 每秒供料 | 排出目标 | 三星交换次数 |
| --- | --- | --- | --- | --- |
| 王室金库 | 右侧料井与下方出口连通 | 7 | 至少 175 | ≤ 5 |
| 水晶密室 | 右侧不可消除石梁，向左绕行 | 8 | 至少 205 | ≤ 7 |

达到排出目标后，还需连续 2 秒低接触压力且离尖刺超过 24 画布像素，才会关闭供料闸门、完成救援。没有血量或耗尽步数失败；交换次数只影响星级。颗粒储备不产生压力，只有已经落入场景并接触盾牌的石头能推动国王。

- 第一关首次开始会高亮一对可交换宝石 5 秒，只作示范，仍需玩家手动交换。
- 鼠标/触屏：先点一颗，再点相邻宝石交换；也支持相邻拖动。未形成横竖三连的交换会弹回。
- 键盘：聚焦画布，方向键移动选择，空格或 Enter 选中/交换。
- 砖块不补位、不落位。两次「重排」只重新排列剩余宝石颜色，保留已打开的空洞与石梁，不暂停落石。
- 「提示」标出建议交换的两颗宝石；若剩余结构无法产生合法三消，需要重排或重新规划。
- 玩法、选关弹窗会暂停；切换后台后需要主动继续。
- 音效默认关闭，Web Audio 本地合成。刷新回第一关，进度归零。

## 本地验证

项目根目录运行 `python3 -m http.server 4188 --bind 127.0.0.1`，打开 `/king-match/`。

```sh
node --test king-match/tests/*.test.cjs
node --test sand-marbles/tests/*.test.cjs
```

`tests/browser-check.js` 是供 Playwright CLI `run-code` 使用的真实鼠标/移动触摸测试，覆盖两关通关、临近尖刺后排流救回、无效交换、暂停、重排、重来和刷新。运行前打开当前服务器的 `/king-match/`；截图写入被忽略的 `output/`。制作人另有独立盲玩和失败验收报告。

## 实现边界

- `levels.js`：两张无初始三连的固定砖图、连续供料、目标与星级。
- `match.js`：纯三消规则、合法交换、保留洞位的颜色重排、路线提示。
- `engine.js`：1/120 秒固定步长、空间桶圆形颗粒碰撞、静态墙/砖/斜坡、动态盾牌、真实出口计数、尖刺触碰判负。接触推力结合实际碰撞冲量和接触负载，具有质量、阻尼、最大行进速度；这是适合小游戏的散料和人物受力近似，不是工程级刚体仿真。
- `renderer.js`：生成 PNG 图集、实体尖刺、受压后退步态、交换/发光/纹理碎裂、出口粒子。消除时刻与砖块失去碰撞同步。触刺后先展示 0.65 秒受惊和接触闪光，再出现失败结果。
- `game.js`：输入、暂停、关卡和结果。`kingGame.snapshot()` 只读诊断，包含生成/队列/排出数、接触力、位置/速度/尖刺距离和阀门状态，没有设胜或改状态接口。
- `assets/PROVENANCE.md`：image 生成资源来源。用户参考图和视频未发布。

所有路径相对，支持 GitHub Pages 的 `/mini-games/` 子路径。无运行时外部依赖、无遥测、无浏览器存储。
