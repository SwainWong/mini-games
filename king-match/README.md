# 国王消消乐

交换相邻宝石，横向或纵向连成至少 3 颗才消除。现有宝石自动向下落，落稳后再次三连会连锁，不补新宝石。黄色石料从满仓上方经斜坡料口持续进入，疏通下方出口才能减轻国王盾前压力。

国王有 **100 HP**。真正碰到身后尖刺时扣 12 HP，持续接触每 0.8 秒再扣 12；实体止挡防止穿刺，离开即停止受伤，不自动回血。HP 归零才失败。

| 关卡 | 排流结构 | 上游供料上限/秒 | 排出目标 | 三星交换次数 |
| --- | --- | --- | --- | --- |
| 王室金库 | 右侧料井与下方出口连通 | 80 | 260 | ≤ 5 |
| 水晶密室 | 右侧固定承重石台，向左绕行 | 85 | 320 | ≤ 6 |

供料能力受真实入口空位、可达空间及料口限制；画外待入库存不产生压力。达到排出目标且 HP>0、离刺超过 12 画布像素、接触力低于抵抗力的 85% 持续 2 秒，才会关闭闸门完成救援。交换次数只影响星级。

- 鼠标/触屏：点两颗相邻宝石或相邻拖动，无效交换弹回。键盘方向键选择，空格或 Enter 确认。
- 下落与连锁期间不接收交换、重排；石头继续流动。承重石台按格对齐，其上下宝石分段下落。
- 两次「重排」只改变落稳宝石的颜色，不补回顶部空位，也不移动石台。
- 「提示」考虑重力和连锁后的排石路径；首次第一关提供一次交换示范高亮。
- 暂停、玩法/选关弹窗和后台状态停止模拟与扣血；重来和刷新重置 HP、盘面及颗粒。
- 音效默认关闭，Web Audio 本地合成。无登录、存储、遥测或外部运行依赖。

## 验证

项目根目录运行 `python3 -m http.server 4188 --bind 127.0.0.1`，打开 `/king-match/`。

```sh
node --test king-match/tests/*.test.cjs
node --test sand-marbles/tests/*.test.cjs
```

`tests/browser-check.js` 是 Playwright 真实鼠标/触摸回归函数。制作人独立试玩记录在 `docs/revisions/king-hp-gravity-v3-review.md`。开发截图和测试输出只写入忽略的 `output/`。

## 实现边界

- `match.js`：三消、重力、全连锁、路线提示；四种宝石，无初始自动匹配。
- `engine.js`：1/120 秒固定步长，真实圆形颗粒与数值空间桶、动态盾牌、移动宝石碰撞体、HP冷却、出口守恒。落位绘制与碰撞使用同一 y，旧位置没有幽灵碰撞。
- `renderer.js`：image 生成 PNG、实际几何对应斜坡/石台/尖刺、交换发光碎裂、加速下落、连锁、受伤红闪及浮字。
- 接触压力采用碰撞冲量、穿透修正及实际贴盾颗粒数的小游戏近似，并非工程级散料仿真；宝石轨道重力为受约束运动。
- `kingGame.snapshot()` 只读诊断含 HP、粒子守恒、仓体填充指标、真实压力、盾位置和下落阶段，不提供修改状态接口。
- `assets/PROVENANCE.md` 记录生成素材。原始用户参考图视频不发布。v1/v2 文档保留作历史，本版规则以 v3 为准。

所有路径相对，支持 GitHub Pages `/mini-games/` 子路径。
