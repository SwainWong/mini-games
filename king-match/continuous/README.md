# 国王消消乐：A → B 连续旅程

连续关卡机制体验版，入口 `king-match/continuous/index.html`。从仓库根目录启动任意静态 HTTP 服务，打开该路径即可运行。图片全部通过相对路径复用上一层的本地素材；原单关入口不变。

## 操作与胜负

1. 点击“开始 A 关”。交换相邻宝石，横向或纵向三连会消除，现有宝石向下补空位，不生成新宝石。
2. 同一批石料一边堆在国王的盾前、把他推向门刺，一边经消除打开的底口流进配重斗。真正落入斗内的每颗石头只计重一次。
3. A 需要超过 42 颗配重、B 需要超过 68 颗。配重斗下降会通过绳索吊起门，到顶后锁定。宝石消除数量不直接计重，开门也不直接判胜。
4. 门已锁定后点“前进”，国王自动穿门；存活到达 P1 才完成 A。镜头跟随国王走上连廊，乘自动入场升降台下降至 B 的防守位置。
5. 点击“开始 B 关”才启动 B 的独立石料、棋盘和机关，生命恢复到 100 HP。B 必须重新开自己的门并到达 P2，才完成整段旅程。

门刺接触会周期性扣血，HP 归零失败。“本段重来”只重置当前段；在 B 重试保留 A 的完成状态。刷新从 A 重新开始，没有持久存档。暂停、后台隐藏与玩法弹窗会冻结模拟；暂停也冻结人物动作。

支持鼠标点击两格、拖动交换和触摸；键盘方向键移动焦点，空格/回车选格。提示标出一组合法交换；重排最多两次，只改剩余宝石颜色，保留空位和石料。

## 地图结构

```text
A：单消除区 → 实际落石配重 → A 门 → P1
                                    ↓
                 上层连廊 → 自动入场升降台
                                    ↓
B：单消除区 → 独立落石配重 → B 门 → P2
```

连廊与升降台属于已完成 A 后的保护路段，不需要额外消除。行走期间停止前一段的危险模拟，B 在入场开始前保持静止。

## 验证与边界

运行 `node --test king-match/continuous/tests/engine.test.cjs`。测试涵盖接触压力、实际入斗唯一计重、双关隔离、留宝石通关、升降台同步、暂停、重试与终点镜头。

目前是有限初始石料、4×4 棋盘的机制原型，两个关卡均有一次正确交换即可开门的解法，优先验证连续性与因果，尚未进行难度曲线设计。颗粒接触和重量门为二维小游戏近似，不是工程物理仿真。浏览器触控模拟不等于实体手机验收。
